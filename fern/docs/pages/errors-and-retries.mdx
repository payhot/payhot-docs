## Идемпотентность

Для операций создания передавайте заголовок `Idempotency-Key`. Ключ должен обозначать одну бизнес-операцию и оставаться тем же при повторе запроса.

Не используйте один ключ с разными телами запроса. Для новой операции создайте новый ключ.

## Формат ошибки

Ошибки API содержат:

- `code` — стабильный код ошибки;
- `message` — понятное описание;
- `request_id` — идентификатор для обращения в поддержку;
- `retryable` — можно ли безопасно повторить запрос;
- `action` — рекомендуемое действие.

## Когда повторять запрос

1. Проверьте `retryable` в теле ответа.
2. Если сервер вернул `Retry-After`, выдержите указанную задержку.
3. Для той же операции повторите исходное тело и исходный `Idempotency-Key`.
4. При неизвестном результате сначала запросите состояние созданного объекта.

<Warning>
Не создавайте новую выплату или новое списание только из-за обрыва соединения. Сначала повторите идемпотентный запрос или проверьте статус операции.
</Warning>
